

## 为什么要写测试

* Salesforce 要求 **Apex 代码部署到生产 org 时总体覆盖率 ≥ 75%**（且相关触发器/类需要各自有测试）。
* 测试确保变化不会破坏既有功能（回归防护）。
* 在测试中你可以控制环境（模拟用户、控制异步执行、mock 外部服务），更容易定位问题。

---

## 测试类的基本结构

* 使用 `@isTest` 标注一个类为测试类（或 `@isTest(SeeAllData=true)` —— 不推荐）。
* 测试方法：

  * 早期写法：`static testMethod void myTest(){}`（旧）
  * 推荐写法：`@isTest static void myTest(){}` 或 `@IsTest` 修饰整个类，方法无需注解。
* 最好 **不要** 使用真实 org 数据（`SeeAllData=false` 默认），测试用数据都由测试类自己创建。

```apex
@isTest
private class MyTestClass {
    @isTest static void exampleTest() {
        // arrange: 建立测试数据
        // act: 调用被测方法或执行 DML（触发器等）
        // assert: 使用 System.assert* 验证结果
    }
}
```

---

## 创建测试数据 — 推荐做法

* 在测试类里用 `insert` 创建 Account / Contact / 自定义对象记录，保持 `SeeAllData=false`（默认）以保证测试隔离性。
* 如果多个测试方法都需要共享数据，使用 `@testSetup` 方法创建公共数据（该方法只运行一次并对该测试类下所有测试方法共享，只读）。

```apex
@isTest
private class SampleTests {
    @testSetup
    static void setupData() {
        Account a = new Account(Name='Test Account');
        insert a;
        // 后续测试方法可以查询到此 Account（只读）
    }
}
```

## 常用测试方法与 API

* `Test.startTest()` / `Test.stopTest()`：重置 governor limit 计数，并在 `stopTest()` 时强制执行所有排队异步（Queueable、Future、Batch finish 等），用于测试异步代码。
* `Test.getStandardPricebookId()`：测试中获取标准价目表 ID（示例）。
* `Test.isRunningTest()`：判断当前是否在测试上下文（少用）。
* `Test.setMock(HttpCalloutMock.class, mockInstance)`：模拟 HTTP callout。
* `Test.setFixedSearchResults(List<Id>)`：在测试 SOSL 结果时固定返回（高级）。
* `Test.loadData(sObjectType, staticResourceName)`：从静态资源 CSV 加载数据到测试（便捷）。

## 示例 1：简单服务类的单元测试

### 被测类（简单服务）

```apex
public class AccountService {
    // 业务：创建 Account 并返回 Id
    public static Id createSimpleAccount(String name) {
        Account a = new Account(Name = name);
        insert a;
        return a.Id;
    }

    // 业务：根据 Id 获取 Account 名称
    public static String getAccountName(Id accId) {
        return [SELECT Name FROM Account WHERE Id = :accId].Name;
    }
}
```

### 测试类

```apex
@isTest
private class AccountServiceTest {
    @isTest static void testCreateAndGetName() {
        // arrange: 测试数据（这里被测方法会插入数据，故无需预建）
        
        // act: 调用被测方法
        Id accId = AccountService.createSimpleAccount('UnitTest Account');

        // assert: 验证结果
        System.assertNotEquals(null, accId, '应该返回新 Account 的 Id');

        String name = AccountService.getAccountName(accId);
        System.assertEquals('UnitTest Account', name, 'Account 名称应一致');
    }
}
```

> 注释中分为 arrange / act / assert 三段，便于阅读与维护。

## 示例 2：测试触发器（Trigger）行为

假设有一个 Trigger：`after insert` 时为每个 Account 创建一个 Contact。我们测试这个行为。

### Handler（简单示例）

```apex
public class AccountTriggerHandler {
    public static void afterInsert(List<Account> newList) {
        List<Contact> cons = new List<Contact>();
        for (Account a : newList) {
            cons.add(new Contact(LastName = a.Name + ' Contact', AccountId = a.Id));
        }
        if (!cons.isEmpty()) insert cons;
    }
}
```

### Trigger

```apex
trigger AccountTrigger on Account (after insert) {
    if (Trigger.isAfter && Trigger.isInsert) {
        AccountTriggerHandler.afterInsert(Trigger.new);
    }
}
```

### 测试 Trigger

```apex
@isTest
private class AccountTriggerTest {
    @isTest static void testAfterInsertCreatesContact() {
        // arrange
        Account a = new Account(Name='ACME');
        insert a; // 触发器会执行 AccountTriggerHandler.afterInsert

        // assert: 查 Contact 是否被创建
        List<Contact> cons = [SELECT Id, LastName, AccountId FROM Contact WHERE AccountId = :a.Id];
        System.assertEquals(1, cons.size(), '应创建一个 Contact');
        System.assert(cons[0].LastName.contains('ACME'), 'LastName 应包含 Account 名称');
    }
}
```

## 示例 3：测试 Batch Apex（包括 start 返回 QueryLocator / Iterable）

### Batch（QueryLocator 方式）

```apex
public class ActivateAccountsBatch implements Database.Batchable<Account> {
    public Database.QueryLocator start(Database.BatchableContext bc) {
        return Database.getQueryLocator([SELECT Id, Active__c FROM Account WHERE Active__c = false]);
    }
    public void execute(Database.BatchableContext bc, List<Account> scope) {
        for (Account a : scope) a.Active__c = true;
        update scope;
    }
    public void finish(Database.BatchableContext bc) {
        // 可以发通知或链式启动下一个 Batch
    }
}
```

### 测试 Batch（使用 Test.startTest / Test.stopTest）

```apex
@isTest
private class ActivateAccountsBatchTest {
    @testSetup
    static void createData() {
        // 创建 500 条测试 Account（确保触发多个批次）
        List<Account> list = new List<Account>();
        for (Integer i=0;i<500;i++) {
            list.add(new Account(Name='A'+i, Active__c=false));
        }
        insert list;
    }

    @isTest static void testBatchActivation() {
        // arrange done by @testSetup

        // act: 执行批处理，并把批次大小设为 200
        Test.startTest();
        Database.executeBatch(new ActivateAccountsBatch(), 200);
        Test.stopTest(); // stopTest 会等待异步完成（包括 Batch 的 execute/finish）
        
        // assert: 所有 Account 的 Active__c 都变为 true
        Integer cnt = [SELECT count() FROM Account WHERE Active__c = true];
        System.assertEquals(500, cnt, '所有 Account 应被激活');
    }
}
```

### Batch（Iterable 方式）示例与测试（当数据来源非 SOQL）

```apex
public class CustomIterableBatch implements Database.Batchable<String> {
    public Iterable<String> start(Database.BatchableContext bc) {
        // 举例：从外部构造 ID list（测试时返回小集合）
        return new List<String>{'001A','001B','001C'};
    }
    public void execute(Database.BatchableContext bc, List<String> scope) {
        // 使用字符串 ID 做逻辑（实际场景中先用这些 ID 查询或调用外部系统）
        System.debug('Processing: ' + scope);
    }
    public void finish(Database.BatchableContext bc) {}
}

@isTest
private class CustomIterableBatchTest {
    @isTest static void testIterableBatch() {
        Test.startTest();
        Database.executeBatch(new CustomIterableBatch(), 2);
        Test.stopTest();
        // 这里可以根据日志或 side-effect 做断言
        System.assert(true, '可检查日志或外部 mock 状态');
    }
}
```

## 示例 4：`@testSetup`、`Test.runAs`、HttpCalloutMock 用法速览

### @testSetup（共享固定数据）

```apex
@isTest
private class UtilTest {
    @testSetup
    static void setup() {
        // 此方法只执行一次，产生的记录对本测试类所有测试方法可见（只读）
        insert new Account(Name='Shared');
    }

    @isTest static void useSharedData() {
        // 可以查询 @testSetup 创建的数据
        System.assertEquals(1, [SELECT count() FROM Account WHERE Name='Shared']);
    }
}
```

### Test.runAs（模拟不同用户上下文）

```apex
@isTest
private class RunAsTest {
    @isTest static void testRunAs() {
        // 创建一个非管理员用户（示例）
        Profile p = [SELECT Id FROM Profile WHERE Name='Standard User' LIMIT 1];
        User u = new User(Alias='tuser', Email='t@x.com', EmailEncodingKey='UTF-8',
                          LastName='RunAs', LanguageLocaleKey='en_US',
                          LocaleSidKey='en_US', ProfileId=p.Id,
                          TimeZoneSidKey='Asia/Tokyo', Username='runas'+DateTime.now().getTime()+'@example.com');
        insert u;

        System.runAs(u) {
            // 在此代码块里以 u 的权限执行
            // 例如测试某个受权限限制的逻辑
        }
    }
}
```

### 模拟 HTTP Callout（HttpCalloutMock）

* 如果被测代码做 HTTP callout，测试中必须用 `Test.setMock()` 提供一个实现 `HttpCalloutMock` 的假实现。

```apex
// Mock 实现
public class SimpleHttpMock implements HttpCalloutMock {
    public HTTPResponse respond(HTTPRequest req) {
        HttpResponse res = new HttpResponse();
        res.setHeader('Content-Type','application/json');
        res.setBody('{"result":"ok"}');
        res.setStatusCode(200);
        return res;
    }
}

// 测试中使用
@isTest
private class CalloutTest {
    @isTest static void testCallout() {
        Test.setMock(HttpCalloutMock.class, new SimpleHttpMock());

        Test.startTest();
        // 调用会触发 HTTP callout 的方法
        // MyCalloutClass.doCallout();
        Test.stopTest();

        // 断言 callout 结果处理逻辑
        System.assert(true);
    }
}
```

## 断言（Assertions）详解

* `System.assert(Boolean condition, String msg)`：断言为真。
* `System.assertEquals(expected, actual, String msg)`：断言相等（注意顺序）。
* `System.assertNotEquals(unexpected, actual, String msg)`。

示例：

```apex
System.assertEquals(1, myList.size(), '列表长度应为 1');
System.assert(myRec != null, '记录不应为 null');
```

## 常见注意事项与最佳实践总结

* **不要使用 SeeAllData=true**（除非绝对必要），测试应独立、可重复。
* **使用 @testSetup** 创建共享测试数据，减少重复建表开销提升速度。
* **用 Test.startTest()/Test.stopTest()** 包裹异步或耗资源的调用以重置 Governor limits 并强制执行异步任务。
* **测试要断言行为（assert）而非仅仅执行代码**。只跑代码但不断言很难发现回归。
* **覆盖异常路径**（比如传入非法参数、DML 异常）以保证健壮性。
* **模拟外部依赖**（HTTP callout 使用 HttpCalloutMock），不要依赖真实外部系统。
* **批量化测试**：模拟批量数据（触发 Trigger / Bulk 执行路径），避免仅测试单条数据分支。
* **不要假设执行顺序**（trigger flow, workflow 等），在测试中明确预期。
* **测试类也要有易读注释**，按 arrange/act/assert 模式组织代码。
